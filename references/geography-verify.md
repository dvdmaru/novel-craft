# 地理真實性驗證（geography-verify）

> AUDITOR 維度 27 ＋ 移動章「事前真相卡」SOP。
> 適用於建立在**真實世界地理**上的作品（都市 / 現代 / 歷史寫實）。架空世界（玄幻 / 仙俠 / 虛構大陸）**不啟用**——其地理由 story-bible 自洽，用維度 2/3 把關即可。

---

## 0. 核心原則（三條邊界，先讀這段）

本維度的目的是**確認真實地理以增加代入感**，不是把地圖搬進稿子。動手前先記死這三條：

1. **真相卡是背景，不是稿子。** 查證的產出是給 writer 的地理基準，**不是要寫進正文**。代入感來自「作者真的知道這裡」，靠的是**選對 1–2 個在地細節**，不是把 GPS 導航式路徑（走過 A、經過 B、到達 C）塞滿段落——那會直接觸發維度 17（流水帳）。精確在後台，克制在前台。
2. **只查得到「和平時期地理基準」。** 距離、方位、路網拓樸、設施位置與設計用途是 [已查]；末世 / 災後的路況劣化（橋斷、封路、淹水、設施被徵用改用途、聚落廢棄）是 [創作]，**查不到、由作者決定**。兩者在真相卡分欄，不可混。把創作當查證會誤導，把查證當創作會丟掉免費的真實感。
3. **這是既有「named entity 不可憑直覺」戒律的空間軸延伸。** 路名、站名、行政區、地標都是 named / 機制性事實，跟人物職稱、組織全名、認證範圍同一個 family——同樣**不可憑名稱直覺縮短或腦補**（參見 sealed 戒律「named entity 必查 source」「機制性事實 fact-check」：「台北市足球協會」應為「台北市體育總會足球協會」、「FIFA 認證」只認證人工草皮等踩坑案）。本維度等於把 book-rules 科學硬約束「地理距離」那條從**寫死的一句話**升級成**per-route 真查**。

> 一句話：**查證為了不出戲（底線）+ 撞出真實張力（加值），但落到正文只留克制的一兩筆。**

---

## 1. 何時啟用

- **配置**：`realWorldGeography: true`
- **觸發章節**：移動章、路線決策章、偵查章、首次抵達新地點的布局章。
- **不觸發**：靜止章（同一場所內部，如收容所內、室內對峙）——地理風險低，不跑，省力。

判準一句話：**只要角色在真實地圖上「移動」或「指認方位 / 距離 / 設施」，就跑。**

---

## 2. 為什麼（代入感原理）

真實地理錯誤對在地讀者是「立刻出戲」的硬傷——路名、行政區、車站、方位、距離、步行時間都是 **named / 機制性事實**，地位等同維度 12（年代考據）之於歷史劇。

但本維度的價值不只「不出戲」（負向底線）。真查常會**撞出真實張力**（某官方設施的設計用途與本作災害不符、某路段的地形障礙、某方位的日照），那是讓虛構更聰明的素材（正向加值）。**geo-verify 不是橡皮圖章打勾，是錨點 + 張力雙產出。**

> 已驗證案例（熱穹 Ch16）：查金湖路最近的官方避難收容處所＝大湖公園（戶外、震災用）。發現「震災避難＝往空曠跑」與本作「熱災避難＝往遮蔭室內躲」**邏輯相反**——於是國軍 realistically 不會啟用該官方點、改徵用室內學校。真查同時給了錨點（大湖公園站、成功路五段、秀湖里）與一個讓設定更聰明的張力。

## 3. 兩種插法（事前 > 事後）

| 插法 | 階段 | 作用 |
|------|------|------|
| **事前真相卡（主力）** | ARCHITECT 後、WRITER 前 | 產出「路線真相卡」，writer 拿著它寫，代入感**內建**而非補丁 |
| **事後 audit（補網）** | AUDITOR | 對已寫章節掃殘留地理 bug |

---

## 4. 工作流程

1. **抽取地理宣稱**：從大綱 / 正文列出所有可驗證的地理事實——起訖地、途經地、路名 / 編號、分段距離、移動時間、方位、地形障礙、設施名稱與性質。
2. **真查錨點**（用地圖 / 官方地理工具，**不可憑直覺**；台灣綁定見附錄 A）：
   - 行政區歸屬（縣市 / 區 / 里）
   - 最近的真實設施（車站、收容處所、醫院、地標）及其屬性
   - 兩點直線距離、方位
3. **deterministic 幾何**：用 `scripts/geo_verify.py` 算分段直線距離（haversine）、累計、方位（bearing）、合理移動時數。
4. **產出路線真相卡**（模板見 §5）。
5. **劃清虛構邊界**（見 §6）。

---

## 5. 路線真相卡模板

```
# 路線真相卡 | ChNN「章名」

## 已查（真實基準，可查證）
- 起點：<地名>（行政區 縣市/區/里）座標 <lat,lng>
- 訖點：<地名> 座標 <lat,lng>
- 途經：<…>
- 分段直線距離：A→B x.x km / B→C y.y km｜累計 z.z km（haversine）
- 公路距離估算：累計 × <繞路係數 1.2–1.4> ≈ w km
- 方位：A→B 朝 <N/NE/E/…>（bearing <deg>°）
- 合理移動時數：夜行 15–25 km/夜 → 約 n 夜；步行速 4–5 km/h
- 真實設施錨點：<最近車站 / 收容所 / 地標 ＋ 屬性>

## 創作（作者決定，非查得，標 [創作]）
- 路況劣化：<橋斷 / 封路 / 淹水 / 管制>
- 設施改用途：<官方震災點被徵用為室內安置點>

## 寫作提醒
- 只挑 1–2 個在地細節入正文，避免 GPS 導航式流水帳（維度 17）
- 方位與太陽 / 天氣連動（西曬、盆地地形）才是「體感真實」
```

---

## 6. 虛構邊界（最重要、最易踩）

真查只給 **「和平時期地理基準」**：距離、方位、路網拓樸、設施位置與**設計用途**。

末世 / 災後的**路況劣化**（橋斷、封路、淹水、設施被徵用改用途、聚落廢棄）是**作者創作，不是查得到的**。

→ 真相卡必須把 `[已查]` 與 `[創作]` 分欄。把創作當查證會誤導；把查證當創作會丟掉免費的真實感。

---

## 7. 嚴重等級

- **critical**：可驗證的硬性地理事實錯誤——路名 / 行政區 / 車站張冠李戴、方向相反、距離量級錯（把 10 km 寫成 100 km）。
- **warning**：距離 / 時間估算不合理（夜行一夜走 60 km）、繞路係數明顯失真、方位與實際偏差大。
- **info**：可優化的在地細節（方位未與西曬連動、可換更精確地標、設施屬性未利用）。

---

## 8. 與其他維度的關係

- **維度 2（時間線）**：管「故事內」距離–時間自洽；本維度管「對照真實世界」是否成立。一內一外，互補。
- **維度 17（流水帳）**：本維度產出是**背景真相卡，不是要全塞進正文**；塞太多在地細節反而觸發維度 17。
- **維度 12（年代考據）**：同屬「真實世界對照」family——維度 12 管時間軸，維度 27 管空間軸。

## 附錄 A：台灣地理工具綁定（twinkle-hub MCP）

| 用途 | 工具 |
|------|------|
| 地址正規化（全形→半形、台→臺、縣→市升格） | `twtools-normalize_taiwan_address` |
| 座標 → 縣市 / 區 / 里 | `twtools-lookup_district_by_coord(lng, lat, unit)` |
| 行政區查詢（名稱 / 郵遞區號） | `twtools-lookup_administrative_district(name)` |
| 捷運線 / 站（北捷 / 高捷 / 桃機 / 中捷） | `twtools-lookup_mrt_line(站名)` |
| 圖資主題清單 | `twtools-list_geo_themes` |
| 座標 → 最近 POI | `twtools-query_geo_theme_nearest(theme_id, lng, lat)` |

**常用 theme_id**：
- `o4XTdRod` 避難收容處所（回傳 sheltercapacity / 室內外 / 適用災害 / 是否收弱勢）← **末世安置點 / 避難所錨點**
- 其餘主題：防空疏散避難設施、寺廟、宗教法人、教會、測速執法點、歷史交通事故

**純幾何（不需 MCP）**：距離 / 方位 / 夜行時數 → `scripts/geo_verify.py`

> 其他地區（非台灣）作品：用通用地圖服務（OpenStreetMap / 地圖 API）取座標與設施，再餵 `geo_verify.py`。SOP 與真相卡模板不變，只換錨點來源。
