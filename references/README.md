完整的網路文學創作規則與狀態管理系統

## 文件導覽

### 核心狀態管理系統

#### 📋 **state-schemas.md** | 七份真相文件格式定義
完整的狀態追蹤系統，用於管理長篇小說的敘事進度、資源流動、伏筆網絡與角色演變。

**包含內容**：
1. **current-state.md** - 當前狀態卡（主角狀態、敵對者清單、已確立真相、核心衝突）
2. **particle-ledger.md** - 資源賬本（修為進度、資源流動追蹤、衰減公式）
3. **pending-hooks.md** - 伏筆池（懸念管理與回收追蹤）
4. **chapter-summaries.md** - 章節摘要（每章進度快速查閱）
5. **subplot-board.md** - 支線進度板（平行故事線管理）
6. **emotional-arcs.md** - 情感弧線（角色心理與情緒變化追蹤）
7. **character-matrix.md** - 角色交互矩陣（相遇記錄與信息邊界）

**適用於**：所有題材與小說類型

### 題材特定規則

#### 🏮 **genre-xuanhuan.md** | 玄幻題材完整規則
基於網路文學主流的玄幻設定系統。

**核心內容**：
- 4種章節類型（戰鬥、布局、過渡、回收）
- 6種爽點類型定義與撰寫方式
- 修為體系與戰力設定（跨階戰鬥規則）
- 資源衰減公式計算
- 高頻詞清單與替代建議
- 玄幻十大禁忌與語言鐵律

**關鍵規則**：
- 三章內必有明確反饋
- 修為晉升應與故事時間線匹配
- powerScaling = true / numericalSystem = true

---

#### 🏙️ **genre-urban.md** | 都市題材完整規則
當代或特定歷史時期的現實背景創作規則。

**核心內容**：
- 5種章節類型（商戰、社交、布局、過渡、回收）
- 爽點類型（商戰勝利、身份顯露、人脈拓展等）
- 年代約束規則（科技、通訊、經濟背景）
- 行業邏輯驗證
- 人物塑造與社會風俗

**關鍵規則**：
- 每2-3章一個小回報
- 商業邏輯必須自洽
- 手機、軟體使用需符合年份

---

#### ⚔️ **genre-xianxia.md** | 仙俠題材完整規則
中國古代背景的修仙與武俠融合體系。

**核心內容**：
- 6種章節類型（決鬥、劫難、修煉、人事、行走、宿命）
- 修為階級與劍法等級（15層修為 + 6層劍法）
- 劍術進度規則
- 動靜節奏的交替（避免持續激烈或靜滯）
- 古韻對白與禪意表達

**關鍵規則**：
- 品性與修為雙向成長
- 劍法突破需要關鍵事件支撐
- 決鬥應體現智謀與品性

---

#### 👻 **genre-horror.md** | 恐怖題材完整規則
通過心理懸念與不確定性喚起讀者恐懼的系統。

**核心內容**：
- 6種章節類型（發現、升溫、高潮、揭示、崩潰、終局）
- 「釋放與收緊」的波動節奏
- 驚嚇 vs 懸念的區分與運用
- 感官細節的重要性（聽覺、觸覺、嗅覺）
- 恐怖美學原則

**關鍵規則**：
- 恐怖應60%懸念 + 40%驚嚇
- 連續3章高強度需要緩解
- 想象的恐怖 > 直視的恐怖
- 細節真實感增強代入感

## 使用工作流

### 1. 新小說開工

```
1. 建立七份真相文件（基於 state-schemas.md 的模板）
2. 選擇題材，學習對應的 genre-*.md 規則
3. 明確修為體系、章節類型、爽點分布
4. 第一次布局時，填寫 current-state.md 與 pending-hooks.md
```

### 2. 每章完成後

```
1. 更新 chapter-summaries.md（新增該章記錄）
2. 更新 pending-hooks.md（標記伏筆推進狀態）
3. 更新 particle-ledger.md（記錄資源變化）
4. 更新 emotional-arcs.md（記錄角色心態變化）
5. 更新 character-matrix.md（記錄新相遇）
6. 檢查該章節類型的撰寫清單
```

### 3. 定期審視（每5-10章）

```
1. 檢查伏筆密度：是否無人推進超過8章的伏筆
2. 檢查節奏分布：是否有連續3章相同類型
3. 檢查爽點頻率：是否符合該題材的間隔
4. 檢查角色一致性：決定與言行是否符合既有設定
5. 檢查數值系統（若有）：修為進度是否合理
```

## 常用檢查清單

### 每章撰寫前：檢查 current-state.md
```
□ 主角當前位置與狀態
□ 當前敵手與威脅等級
□ 已確立真相（不能推翻）
□ 當前核心衝突（本章應推進哪方面）
```

### 每章撰寫中：參考對應的爽點類型
```
玄幻：6種爽點（打臉、升級、收益、智鬥、身份、底牌）
都市：6種爽點（商戰、身份、人脈、計謀、危機、秘密）
仙俠：無明確爽點，重點在品性與決鬥的意義
恐怖：懸念型爽點（細節驚悚、規則發現）
```

### 每章撰寫後：執行對應的撰寫檢查清單
```
state-schemas.md 文尾有各題材的完整檢查清單
genre-*.md 文尾均有撰寫檢查清單
```

## 常見問題

**Q：一定要用七份真相文件嗎？**
A：不一定。對於短篇（< 30章）可以簡化為：current-state + chapter-summaries + pending-hooks。

**Q：題材混合怎麼辦（如：都市 + 超自然）？**
A：優先遵循主題材的規則，將次題材的特色融入。例如：都市超自然 = 遵循 urban.md + 參考 horror.md 的懸念章節。

**Q：這些規則是硬性的嗎？**
A：95%的規則有基本原因（讀者心理、市場反饋）。創意突破可以，但應確保邏輯自洽。

**Q：如何驗證我的小說符合規則？**
A：使用對應題材的撰寫檢查清單，每章完成後逐項檢查。
